# Sense2Act 后端用户故事与验收条件

更新：2026-10-14。本后端是招投标商机发现的数据与流程平台；爬虫、检测算法和 Agent 循环由外部服务实现。下列故事总结平台功能，接入修复对应本文件末尾的验收记录。

## US-01 信息源管理与健康监控

作为管理员，我希望配置和启停信息源、安排采集时间并查看运行健康，以便持续监控目标网站。

- 可以创建、修改、停用和查询信息源，保存 URL、adapter 和私有配置。
- 采集时间采用 Spring 六段 cron；没有 cron 的源可手动触发。
- 手动触发后，爬虫下一次轮询能看到到期任务。
- 连续失败 3 次标 degraded、10 次标 down，成功后恢复 ok，并保存错误记录。
- 有历史文档的信息源不能直接删除，可以停用；写操作仅管理员可执行。

## US-02 可靠地接收采集文档

作为爬虫服务接入方，我希望批量提交公告、政策和新闻，并得到准确的接收统计，以便重试不会重复入库，个别坏数据也不会阻塞正常数据。

- 使用 X-Internal-Key 读取到期信息源及完整配置、提交文档和上报运行结果。
- 按归一化 URL 和 content_hash 去重；并发重复推送只新增一条，其他计为 duplicates。
- 单批最多 500 条；每条独立提交，金额越界或数据库错误仅使该条计为 failed。
- accepted 和 document_ids 只包含实际提交的文档；后续正常条目仍可接收。
- 可保存 raw_html 原文快照；机构名称归一，按机构及类别更新统计基线。

## US-03 文档检索与原文核验

作为分析师或查看者，我希望按关键词、机构、区域、类别、金额和日期寻找文档并查看原文，以便判断商机是否值得跟进。

- 提供分页列表、详情、关联信号、机构近期文档与原文快照。
- 金额以小数字符串输出，分页采用 items/total/page/page_size。
- 配置 embedding 服务后可以语义检索和关键词/向量融合检索；端点不可用时降级为关键词。
- 文档和机构的只读接口同时接受用户 JWT 和内部服务 key。

## US-04 检测服务获取规则与原料

作为信号检测服务接入方，我希望一次获取待检测文档、统计基线、关注画像和启用规则，以便按平台当前版本产出信号。

- detection-queue 提供文档、org_stats、profiles，并新增 rules。
- 规则包含 id、version、type、params、weight 和 enabled；只下发启用版本。
- 也可用 X-Internal-Key 调用 GET /internal/signal-rules，无需管理员账号。
- 管理员生成新版本或停用规则后，下一次读取反映最新配置。
- 检测队列金额为字符串；完成扫描后可批量标记文档已扫描。

## US-05 信号决策与调查触发

作为分析师，我希望查看规则命中详情，选择确认、忽略或调查，以便把深入调查成本集中到有价值的信号。

- 支持按状态、规则类型、分数、机构和日期查询信号。
- 相同 document + detector + hits 的推送幂等，保留算法和规则版本留痕。
- 达自动阈值的信号创建 created 调查；其他信号等待人工决策。
- 忽略必须填写理由，决策记录进入反馈数据；已忽略或已有调查的信号不能随意重复开调查。

## US-06 调查领取与成本控制

作为 Agent 服务接入方，我希望领取调查并获得上下文，同时由平台限制轮次、预算和并发，以便调查运行有边界、成本可追溯。

- start 以 CAS 占用 created 调查，并检查最大并发数；冲突返回 40901。
- context 返回信号、文档、问题、证据和剩余预算；新增 questions 全量清单，保留 open_questions。
- 每次步骤上报检查调查状态、max_rounds 和 token_budget。
- 极大 token_usage 不会溢出记账；并发上报不会覆盖消耗、突破预算或重复分配步骤序号。
- token_used 与费用按平台累计记录计算，不能由报告自报数覆盖。
- created 调查超过可配置 TTL 未领取，自动失败并回退信号状态。

## US-07 过程留痕、停止与恢复

作为分析师，我希望查看每轮问题、工具使用和反思，并能停止调查，以便理解调查过程并控制后续操作。

- 问题、步骤和预算事件持久化，步骤支持游标分页。
- 停止后信号回退 pending；停止、失败和完成后的新问题修改/步骤写入被拒绝。
- 迟到的步骤会在获得调查锁后重新检查状态，不会继续给已停止调查记账。
- Agent 可以通过内部 steps 查询及 context 恢复已领取任务。
- 步骤可带稳定 request_id；相同内容重试返回原步骤，不重复扣预算；同一 key 改用其他内容返回 40901。
- 恢复方案适用于一个外部 Agent 工作进程；多 worker 的租约和自动接管不在当前平台承诺内。

## US-08 完整证据登记

作为 Agent 服务接入方，我希望登记可复核的证据，以便报告结论能追溯到真实来源。

- 本库证据引用 doc_id；文档必须有发布时间和实际存在的原文快照，否则返回 42201。
- 外部证据需要 URL、标题、发布时间和摘录；后端获取快照、计算 SHA-256 并记录获取时间。
- 外部快照抓取失败或超过大小上限时拒绝登记。
- 证据引用必须属于同一调查；用户可查询证据详情并读取快照。

## US-09 带依据的报告与导出

作为分析师，我希望收到事实、推断和推测明确区分、每条结论都有依据的报告，以便核实后自主决定行动。

- 每条 claim 只能使用 fact/inference/speculation，置信度在 0..1。
- 每条 claim 必须至少引用一条本调查已登记的证据，无依据或越权引用使整份报告拒收。
- 一调查一报告，提交后进入 reporting，complete 后报告 published、信号 confirmed。
- meta 使用调查留痕计算轮次、工具数、token 和费用，保留固定免责声明。
- 提供同步 Markdown 导出；PDF 仍是既定占位，前端应只开放 Markdown 或明确显示 PDF 暂不可用。

## US-10 实时通知与断线续看

作为用户，我希望实时看到调查进度和新信号、报告通知，并在断线后继续查看，以便不会因刷新或网络波动漏掉关键变化。

- 调查流包含启动、轮次、问题、工具、反思、预算和终态事件；全局流包含四类通知。
- 每 25 秒发送心跳，支持 Last-Event-ID，EventSource 可用 ?token= 认证。
- 历史回放和实时到达从同一持久游标有序读取，较新事件不会跳过未发送的历史事件。
- 全局通知日志与业务同事务提交；业务回滚时通知日志也回滚，成功提交后才广播。
- 广播中断时，重连或心跳能够读取已提交记录；单实例原型全员共享通知流。

## US-11 反馈与改进

作为分析师，我希望采纳行动建议、填写评语并标记误报，以便团队积累真实使用反馈并改进检测规则。

- 已发布报告可提交反馈，采纳的建议必须属于该报告。
- 重复采纳幂等，记录用户、评论和 false_positive 标记。
- 信号确认/忽略及报告反馈保存在 feedback_events 中，供后续评估使用。

## US-12 总览与事件图谱

作为查看者，我希望看到文档、信号、调查和报告总量、状态分布与关联事件，以便快速掌握监控结果和跨项目关系。

- 看板提供总量、今日增量和完整状态键。
- 事件提供分页、详情、实体角色、关系图和关联报告。
- 图谱由 Agent 提交的结构化报告产物落库，平台负责查询及引用校验。

## US-13 规则、策略与回测管理

作为管理员，我希望版本化管理规则、调整关注方向和调查策略，并导出回测数据，以便有依据地控制系统行为。

- 修改规则生成新版本，停用旧版，同一规则只有一个启用版本。
- 可管理关注画像、自动触发阈值、最大并发数、默认轮次及预算。
- 可创建回测任务、领取数据集、写回 done/failed 结果，并查看任务状态。
- 回测算法和参数选择由外部评估执行，平台只存输入、状态和结果。

## US-14 前端认证和接口联调

作为前端开发者，我希望有明确的认证文档和可配置的跨域访问，以便直接接入真实后端。

- 用户通过登录接口获取 JWT，角色为 admin/analyst/viewer；viewer 只读。
- 配置允许的 CORS Origin 后，合法预检可完成；未允许的 Origin 被拒绝，跨域配置不会绕过认证。
- 跨域下载能读取 Content-Disposition，限流能读取 Retry-After。
- OpenAPI 声明 JWT 和 X-Internal-Key，区分公开登录、用户接口、内部接口和双认证只读接口。
- 检测文档使用明确 DTO 展示金额字符串及字段类型，其他接口以冻结契约和生成规范为准。

## US-15 环境配置与可部署性

作为部署维护者，我希望通过环境变量配置账号、预算、超时、限流和外部端点，以便环境差异不需要修改代码。

- compose 显式传入种子开关/密码、调查 TTL、token 单价、限流、embedding 超时及 CORS Origin。
- 种子配置只影响首次创建账号；已有账号密码不会因重启而改变。
- PostgreSQL 和快照挂持久卷，API 默认仅绑定本机，代理支持 SSE。
- 部署为单实例；真实域名、证书、来源限制和三个外部服务的连接由部署环境确认。

## US-16 空库演示与验收

作为比赛演示者，我希望从空数据库一键展示完整业务闭环，以便演示不依赖外部服务是否已完成。

- 全链路脚本自动建立合法信息源，使用支持的源类型及六段 cron。
- 演示文档提供发布时间和原文快照，每条报告结论引用已登记证据。
- 源 → 文档 → 信号 → 调查 → 证据 → 报告 → 反馈 → 看板/图谱可完整运行。
- 重复执行创建独立实例，不依赖前序种子脚本。
